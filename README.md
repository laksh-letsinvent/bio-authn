# bio-authN

An eval-first harness for selfie biometric authentication. Runs face matchers over a synthetic corpus and measures accuracy, fairness, calibration, cost, and latency across four AI pillars: **eval**, **governance**, **token economy**, and **infrastructure**.

Live demo: [bio-authn.letsinvent.co.uk](https://bio-authn.letsinvent.co.uk)

---

## What it does

- Runs **ArcFace** and **InsightFace** embedding matchers against a 150-identity synthetic corpus (DigiFace-1M), computing EER, AUC, FAR/FRR, and demographic disparity
- Uses a **Claude VLM** as a second-opinion reasoner on uncertain-band pairs (score near the operating threshold), measuring calibration (ECE) and cost per decision
- Runs a **PAD (Presentation Attack Detection)** track: simulated print and screen attacks, measuring APCER/BPCER/ACER against both a deterministic baseline (FFT + texture) and Claude passive-liveness prompting
- Renders findings in an **interactive portal** — ROC curves, threshold trade-off, bias by group, VLM calibration, PAD results, cost/latency

This is a learning prototype, not a login product. The matching comparison is one part; the measurement instrument around it is the point.

## Architecture

```
corpus/          Synthetic identity corpus (DigiFace-1M subset)
  build_corpus.py   Download, label, pair selection
  attacks.py        Generate simulated PAD attacks (print / screen)

engine/          Matcher adapters
  adapters/
    arcface.py        ArcFace (w600k_r50, direct recognition path)
    insightface.py    InsightFace (buffalo_l, detection+alignment path)
    vlm_cli.py        Claude VLM matching via Claude Code CLI
    pad_baseline.py   Deterministic PAD (FFT high-freq + local variance)
    pad_vlm.py        Claude passive-liveness prompt (api / cli / local)
  registry.py       Adapter factory from config
  accounting.py     Timed execution wrapper

eval/            Evaluation harness
  run_eval.py       Main eval loop (match + PAD tracks, VLM resume)
  metrics.py        EER, AUC, FAR/FRR, APCER/BPCER, calibration, by_group
  schema.py         JSON schema validation (schema_version 1.0)

config/
  eval.yaml         All tunable parameters

results/
  eval_run.json     Versioned result artifact (committed)

portal/          Static dashboard
  index.html
  sections/
    overview.js
    matching.js
    liveness.js
    findings.js     ROC, threshold, bias, VLM calibration, PAD, disagreement
  data/             Pre-generated JSON (committed, regeneratable)

deploy/
  nginx-bio-authn.conf   nginx server block for production
```

## Results (v2 run — synthetic corpus)

| Matcher | EER | AUC | FAR @ thr | FRR @ thr |
|---|---|---|---|---|
| ArcFace | 1.48% | 0.9989 | 0.93% | 2.00% |
| InsightFace | 1.75% | 0.9985 | 0.92% | 2.49% |
| VLM (Claude) | 5.00% | 0.9861 | 0.00% | 13.33% |

| PAD matcher | APCER | BPCER | ACER |
|---|---|---|---|
| pad_baseline (FFT+texture) | 11.5% | 100.0% | 55.8% |
| pad_vlm (Claude passive liveness) | 5.0% | 20.0% | 12.5% |

> Corpus: 150 identities, 2,250 genuine + 7,500 impostor pairs, 200 bonafide + 200 simulated PAD samples. Attacks are OpenCV/PIL degradations of synthetic images — not a real-world attack battery. BPCER=100% on pad_baseline is expected: the FFT detector is calibrated for real camera images; DigiFace-1M renders violate its frequency priors.

## Quickstart

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Build corpus (downloads DigiFace-1M subset, ~2GB)
python corpus/build_corpus.py --config config/eval.yaml

# 3. Generate PAD attack samples
python corpus/attacks.py --config config/eval.yaml

# 4. Run eval (ArcFace + InsightFace free; VLM needs claude CLI or Anthropic key)
python eval/run_eval.py --config config/eval.yaml

# 5. Generate portal data
python portal/scripts/generate_data.py

# 6. Serve portal
cd portal && python -m http.server 8000
```

To resume an interrupted VLM run without re-paying for completed calls:
```bash
python eval/run_eval.py --config config/eval.yaml --resume
```

## VLM transport

Set `vlm_mode` in `config/eval.yaml`:

| Mode | Requires | Cost |
|---|---|---|
| `cli` | Claude Code installed | Per-token (no separate key) |
| `api` | `ANTHROPIC_API_KEY` env var | Per-token |
| `local` | Ollama + LLaVA running | Free |

`cli` is the default — it uses Claude Code headless (`claude -p`) with no separate API key.

## Corpus

Uses [DigiFace-1M](https://github.com/microsoft/DigiFace1M) (Microsoft) — synthetic faces under the Research Use Data Agreement (R-UDA). No real biometric data. Attack images are generated by applying synthetic degradations (blur, colour cast, scan lines, moiré) to corpus images.

## Key design decisions

- **Two frozen contracts**: `MatcherAdapter` interface + `MatchResult` dataclass, and the result JSON schema (`schema_version: "1.0"`). All v2 additions (InsightFace, PAD track) are strictly additive over these.
- **VLM as second opinion, not primary gate**: Claude operates only on uncertain-band pairs (score within ±0.07 of the operating threshold), not on every auth attempt.
- **PAD metrics are separate from matching metrics**: APCER/BPCER (ISO 30107-3) measure liveness gate errors; FAR/FRR measure matching errors. Do not conflate them.
- **Aggregate accuracy ≠ fair accuracy**: `by_group` disparity is measured across sex, age, and skin-tone axes simultaneously.

See `DECISIONS.md` for the full decision log and `ATLAS.md` for domain glossary.
